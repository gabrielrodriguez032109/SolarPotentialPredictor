Solar Potential Predictor troubleshooting
==========================================

Missing data or schema errors
-----------------------------
Run `python src/etl/pipeline.py` from the repository root. It rebuilds both processed
artifacts and includes `kw_total`, which is required for the community capacity value.

Do not import src/etl/pipeline.py to run it. The pipeline only executes when called as
a script; this prevents tests and imports from overwriting generated data.

Location input
--------------
The application accepts coordinates or a five-digit US ZIP code. ZIP lookup resolves
an approximate public ZIP centroid and needs a network connection; if it fails, check
the ZIP or use coordinates. The geographic-match message is the distance from the
submitted/resolved point to the selected tract center, not a prediction-quality score.

Understanding output
--------------------
Community values are direct fields from the nearest Project Sunroof tract. Homeowner
values are a transparent planning calculation using total roof area, local solar yield,
the selected-orientation adjustment, and the tract carbon rate. Neither mode is a
property-specific engineering assessment.

In homeowner mode, optional monthly electricity use sizes toward annual demand without
exceeding roof-area capacity. Optional broad shading adjusts expected production; use
Unknown when no reliable shading information is available. Home square footage is not
used because it is not a dependable substitute for roof area in this calculation.

Model artifacts
---------------
`src/models/random_forest.py` can train and evaluate a Random Forest model. The app
does not need a saved model artifact to present the nearest-tract estimate. If training
fails after a schema change, rebuild processed data first and delete the ignored model
artifact only if you intend to retrain it.

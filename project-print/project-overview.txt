Solar Potential Predictor: Product and Calculation Guide
=========================================================

Purpose
-------
Solar Potential Predictor is a local planning tool built from Project Sunroof-style
census-tract data. It provides two intentionally different views of solar potential.
It is not a property survey, an electrical design, a permit-ready calculation, or a
replacement for an installer assessment.

Analysis modes
--------------

Community Solar Potential Estimate
  Use this to explore the total solar opportunity in the census tract nearest to a
  coordinate. It is for community planning, research, and area comparison.

  The result reports source values from the selected tract:
  - Potential Annual Energy Generation: yearly_sunlight_kwh_total
  - Potential Carbon Reduction: carbon_offset_metric_tons
  - Potential Solar Capacity: kw_total

  These are not the potential of one home. Roof orientation does not change these
  totals, because they already represent the tract's mix of suitable roofs.

Residential Solar Recommendation
  Use this to form a first-pass estimate for one home. It combines the user's total
  roof-area input with the closest tract's solar yield and carbon rate. The following
  homeowner inputs are relevant:
  - Approximate total roof area is required in homeowner mode and caps the planning size.
  - Main usable roof orientation applies a broad production adjustment.
  - Broad shading is optional; Unknown is the default and applies no added adjustment.
  - Average monthly electricity use is optional; when entered, it sizes toward annual
    consumption without exceeding the roof-area capacity.

  Home square footage is intentionally not used. It is not a dependable proxy for
  usable roof area, and the available tract data does not provide a relationship that
  would make it more accurate. Roof condition, panel model, batteries, incentives, and
  utility-rate details are likewise excluded because this app cannot evaluate them
  responsibly without property-specific data.

  The calculation is deliberately explicit:
  - system size = roof area x 0.004 kW/sq ft, limited to 1–15 kW
  - annual production = system size x local annual kWh/kW x orientation adjustment x shading adjustment
  - carbon reduction = annual production x nearest-tract carbon tons/kWh
  - panel count = system size / 0.4 kW, rounded to the nearest whole panel

  The orientation adjustments (South 1.00, West 0.90, East 0.88, North 0.72) are
  planning assumptions, not roof-specific measurements. Shading, roof geometry,
  usable roof area, panel choice, utility rules, and local incentives can materially
  change an installed system's result.

Location and geographic match
-----------------------------
Enter either latitude/longitude or a five-digit US ZIP code. Coordinates select the
nearest tract to the submitted point. ZIP lookup resolves a public ZIP centroid, then
selects the nearest tract and clearly labels that approximation. The geographic-match
message reports the distance to the final selected tract center; it is not an accuracy
score. Coordinates are the more specific option.

How the application works
-------------------------
1. src/etl/pipeline.py reads the raw CSV, removes incomplete rows, and retains the
   solar fields needed by the app and evaluation workflow, including kw_total.
2. It writes data/processed/sunroof_clean.csv and the sunroof_clean SQLite table in
   data/processed/solar.db.
3. src/app/app.py loads that SQLite table and calls the nearest-tract estimate helper.
4. The Random Forest module remains available for model training and evaluation, but
   user-facing community results use the selected source record instead of predicting
   fields that are already present in that record.

Repository map
--------------
- data/raw/: original census-tract CSV
- data/processed/: generated cleaned CSV and SQLite database
- src/etl/pipeline.py: extraction, cleaning, and loading
- src/models/random_forest.py: evaluation model, estimation calculations, validation
- src/app/app.py: Streamlit interface
- tests/test_random_forest_output.py: calculation and regression coverage
- project-print/technical-blueprint.md: technical implementation details
- project-print/debugging-notes.txt: operational troubleshooting

Run the project
---------------
1. Install dependencies: python -m pip install -r requirements.txt
2. Rebuild processed data: python src/etl/pipeline.py
3. Optional model evaluation: python src/models/random_forest.py
4. Run the app: python -m streamlit run src/app/app.py
5. Run tests: python -m pytest -q
